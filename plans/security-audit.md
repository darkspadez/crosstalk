# Security, correctness and performance audit (after phase 3)

Decided with the user on 2026-11-08 (grilling rounds 1-4).

## Decisions
- Threat model: **internet-facing behind a reverse proxy**. One bearer token, hardened: every
  bearer failure on every route counts toward the per-client limiter; `[server]
  trusted_proxies` (CIDR list) decides when `X-Forwarded-For` / `X-Real-IP` is honoured;
  otherwise the socket address.
- Worst case to weight first: **wrong writes to Dispatcharr**; then secret leakage; then
  availability.
- Fix policy: fixes land on the phase-3 branch (PR #4), **one commit per finding class**, each
  with tests. Opus 5.5 finds and fixes; Fable 5.1 reviews the whole series at the end.
- Depth: code review + targeted tests + `cargo audit` + fuzz/property tests for the three input
  parsers (webhook body, lineup JSON, tv-logos tree) + benchmarks.
- Performance: bench every plan phase at 20k channels / 50k streams / 55k EPG entries in
  release; anything over 60 s or scaling worse than n log n is fixed, **and** a hard SLA: every
  action's plan under 10 s at 20k channels. Write request counts reported, not timed.
- Data at rest: provider stream URLs are **never stored** (run rows, CSVs, `stream_health`,
  logs keep stream id + host); fetched from Dispatcharr at probe time only.
- Egress: no destination restrictions; AI requests must still carry no secrets, URLs or
  account names (tested).
- Bridge plugin (`crosstalk-bridge`): **full build** now. Scope: only the writes REST lacks:
  bulk stream-list assignment, bulk `stream_stats`, clear `channel_group`, bulk EPG entry +
  programme rows for generated guides. Transport: Dispatcharr plugin-run API with the
  Dispatcharr admin key, body HMAC-SHA256 over (timestamp, nonce, operation, payload) with a
  shared secret; replay window 5 min + nonce cache; every operation idempotent and allow-listed;
  no reads, no deletes. Secret: generated by `crosstalk bridge secret`, stored in
  `crosstalk.toml [bridge] secret` (0600 file, masked in the UI, never written back from env),
  pasted once into the plugin's settings; `crosstalk bridge rotate` with old+new grace.
  Shipped as a zip from `build.yml`; crosstalk checks the plugin's version at startup and
  disables bridge-backed paths with the reason when missing/old. Rust `BridgeClient` behind the
  existing `StreamListWriter` / `ChannelCreator` seams, off by default.

## Audit areas (parallel, read-only, findings with file:line)
A. Web: auth, CSRF, proxy/IP, limiter, webhook, headers, sessions, static files, error pages.
B. Write safety: every Dispatcharr write path, undo coverage, ownership, cross-process guard,
   partial failures, scheduler/hook/workflow/CLI concurrency, confirm gates, dry-run.
C. Secrets and data at rest: tokens, API key, provider URLs, AI request payloads, config save,
   run rows, CSV, logs, error messages, SQLite file perms.
D. Input handling: webhook body, lineup JSON, tv-logos tree, settings regexes, ffprobe/ffmpeg
   args and output, CSV formulas, path handling, TOML/JSON env overrides.
E. Performance: all plans at scale, request counts, memory, SQLite batching, rayon use.
F. Supply chain and deployment: cargo audit, Dockerfile (non-root, ffmpeg), CI secrets,
   release artifacts, Renovate.
G. Bridge: design + build (after A-F fixes land).

## Fix commits (one per class, in this order)
1. Write safety. 2. Auth/proxy/limiter/webhook. 3. Secrets and URLs at rest. 4. Input parsers +
fuzz tests. 5. Performance. 6. Supply chain/deploy. 7. Bridge. Then the Fable pass.
