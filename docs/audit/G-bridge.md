# Area G: the bridge plugin (design + build, fix 7)

Decision (plans/security-audit.md, "Bridge plugin"): full build; only the writes REST lacks;
plugin-run API with the Dispatcharr admin key plus an HMAC-SHA256 body signature with a shared
secret; 5-minute replay window and nonce cache; every operation idempotent and allow-listed; no
reads, no deletes; secret generated by `crosstalk bridge secret`, stored in `crosstalk.toml
[bridge]` (0600, masked, never written back from the environment), rotation with old+new grace;
zip from build.yml; version check at start-up; `BridgeClient` behind the existing seams, off by
default. The contract is [docs/bridge.md](../bridge.md).

## Deviations from the brief, each deliberate

- **Plugin key `crosstalk_bridge`**, not `crosstalk-bridge`: Dispatcharr derives the key from the
  folder name and its zip import replaces `-` with `_` (`_sanitize_plugin_key`). The product and
  zip keep the `crosstalk-bridge` name; the start-up ping tolerates either spelling.
- **`ChannelCreator` has no bridge implementation**: creating channels is not one of the four
  writes. The `GroupClearer` seam is new, because the "No Group" path had no seam (it was a
  hard-coded per-row refusal in `apply_stages`).
- **Numbers in canonical JSON follow ECMAScript/RFC 8785**, keys sort by code point (not RFC
  8785's UTF-16): "sorted keys, no whitespace" alone does not define floats, and `stream_stats`
  carries them (`source_fps: 29.97`).
- **`upsert_epg` is gated on an operator list of EPG sources** in the plugin's settings, to keep a
  leaked secret from replacing programmes in real XMLTV sources.
- **`ping`'s `key` field** (`current`/`previous`) is kept alongside `configured`: it says which of
  the plugin's two secrets matched during a rotation, not where either is stored.

## Assumptions about Dispatcharr not verified against a running instance

Listed in docs/bridge.md ("Assumptions"): DRF passes `params` through unchanged; a 1 MB body
fits `DATA_UPLOAD_MAX_MEMORY_SIZE` and the image's proxy; Django's cache is shared (Redis) across
uWSGI workers, else nonces are per worker; bulk ORM paths skip `post_save` signals (catch-up
roll-up called explicitly, websocket UI refresh not sent); generated guides read `ProgramData`
for the source type phase 4 picks; the run route's permission is admin; password-type settings
are stored and listed in clear.
