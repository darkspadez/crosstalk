# Matching-rules inventory: where the four matchers differ

Step 3 of `plans/phase-3-lineup.md`. Phase 3 collapses the per-plugin profiles
into ONE engine whose rules are chosen on a labelled corpus (steps 5-6). This
document is the input to that decision: every behaviour where the four matchers
— and the shared core used as-is — disagree, one row per independent rule. It
changes no matching behaviour.

Short tags: **JAN** = EPG Janitor (`reference/Dispatcharr-EPG-Janitor-Plugin/EPG-Janitor`),
**SM** = Stream-Mapparr (`reference/Stream-Mapparr/Stream-Mapparr`),
**CM** = Channel-Mapparr (`reference/Dispatcharr-Channel-Maparr-Plugin/Channel-Maparr`),
**LU** = Lineuparr (`reference/Dispatcharr-Lineuparr-Plugin/Lineuparr`),
**core** = the shared `matching_core.py`.

## Method

`matching_core.py` was confirmed byte-identical across all four plugins
(`md5 cad1b4bbe9f316b4e361c389aa5376d7` via `cmp` on all four copies), so every
row below is a difference in a plugin's own `fuzzy_matcher.py`, its shipped
data (`aliases.py`, channel DBs, station tables), its `country.py` (SM only) or
its `plugin.py` run path. Line numbers are from the pinned checkouts (bare
`:N` = that plugin's `fuzzy_matcher.py`). Each row is one decision (pick one
variant per row; rows do not share a variant) and names the app outcome it
affects: **EPG assign** (which guide entry a channel gets), **stream attach**
(which streams land on a channel), **channel naming** (CM's OTA/premium
rename). Example values were produced by the oracles below
(`scripts/corpus/oracles.py`), not by reading the code.

## Oracles

`scripts/corpus/oracles.py` runs each plugin's own code. `match`/`same` are the
run-path DECISION, not a single matcher entry point: Janitor's
`_find_best_epg_match` with its assignment cut (D02, D06), Stream-Mapparr's
collector plus zone step (C06, D07, Z01), Channel-Mapparr's premium rename
(C06, D10) and Lineuparr's `match_all_streams` as `plugin.py` calls it (D07).
Residual approximations (every EPG entry has programme data; one SM channel
per group with default settings and no streams yet; CM's OTA rename text not
produced and its hash-order ties replaced by input order; no LU lineup country
unless passed) are listed in the module docstring.
`python3 -I scripts/corpus/disagreements.py --self-test` (CI) checks module
isolation and one cited case per decision path.

## Agreements (not rows)

These are identical everywhere and need no decision: number-word folding
(`BBC Three` -> `BBC 3`; JAN `fuzzy_matcher.py:173-178`, CM `:173-178`, core
`:393-404`), CamelCase splitting with the 4-char acronym floor (`DangerTV` ->
`Danger TV`, `MeTV` kept whole; JAN `:643-650`, CM `:829-834`, core `:410-419`),
`process_string_for_matching` keeping `+` (`Disney+`; core `:705-723`), the
`calculate_similarity` code (core `:543-601`; every plugin calls the core's,
but see R01 for rapidfuzz vs fallback), the `_length_scaled_threshold`
definition (core `:603-611`), the callsign denylist table itself (core
`:740-751`; every ladder reads the inherited class attribute), the callsign
ladders' leading `D<digits>-` and `US`/`USA` pre-strip (core `:785-786`, JAN
`:491-492`, CM `:612-613`), and the `remove_country_prefix` opt-in, which no
run path enables (core `:445-453`; SM's `_clean_channel_name` defaults it to
`False` and no caller passes `True`, `plugin.py:4450-4461`, despite the core's
"Stream-Mapparr opts in" comment).

## Where crosstalk's current Rust differs from ALL of them

`crates/crosstalk-matching/src/profile.rs` (planning-time table, two profiles):

1. **`strip_bare_region` is NOT dead.** The table says "core opt-ins, never set by either plugin ... not ported (dead)". Lineuparr sets `_STRIP_BARE_REGION = True` (`fuzzy_matcher.py:351`), the core documents exactly this opt-in (`matching_core.py:104-110, 314-322`), and CM explicitly accepts-and-ignores the flag (`fuzzy_matcher.py:752-753`). Any unified engine must take a position on bare-region stripping (row N10), not drop the flag.
2. **The token-overlap story is three-way, not two-way.** The table ports "Janitor's" override and notes "SM never calls it", but CM has its OWN override text (subset `>=5`, sourced from LU per its docstring; `fuzzy_matcher.py:1038-1123`) and LU uses the CORE version (subset `>=4` + `_is_distinctive`; `matching_core.py:612-703`). The `>=4`-vs-`>=5` subset floor and the distinctive definition (`live`/`now`/`new` + digit handling) are exactly row T01.
3. **The alias row swaps the plugins.** The table's "verbatim key then case-folded fallback" is SM's `alias_lookup` (row A01), not a generic shape; CM's actual lookup is a normalized reverse index with first-wins collision handling (row A02), and JAN/LU add a fuzzy per-alias similarity tier the table omits.
4. **CM and LU entry points are missing entirely.** The table's `fuzzy_match`/`match_all_streams` rows cover only JAN-vs-SM. CM's run path is `fuzzy_match` behind a callsign gate and a token-index pre-filter (rows C06, D10; its `match_all_streams` is never called by `plugin.py`), and LU's `match_all_streams` (country filter, region filter, `+1`/group-header handling, alias-callsign rescue) has its own stage order (row T09).
5. **Thresholds are per-plugin run settings, not engine constants.** SM runs at 85; Janitor's fuzzy floor is 85 but it only assigns at confidence 95 (row D02); CM/LU run at 80 by default with 70/80/90/95 presets (row T10). A single `[matching]` threshold (the phase-3 goal) is a decision, not a port.
