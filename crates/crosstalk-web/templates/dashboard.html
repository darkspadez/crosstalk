Steps run in order through the same runner a manual run uses, so each one gets its own run page, report and status. A step that pauses at its window's end pauses the workflow; the next firing resumes that step. A step may carry its own scope (`scope = "lineup"` or `scope = { groups = "..." }`) instead of the host `[scope]`, and `continue_on_failure` to carry on past its failure; the workflow itself is failed when any step failed. One workflow runs at a time.

{% else %} {% for (event, targets) in hooks.events %} {% endfor %}
EventTriggers

A burst of the same event (several M3U accounts finishing together) restarts the {{ hooks.debounce }} timer, so one run happens after the burst settles. If the target is busy, one follow-up run is queued for when it frees. Unknown events are logged and ignored.

Dispatcharr setup: add an integration of type Webhook with the URL {{ hooks.route }}, a header Authorization: Bearer <{{ hooks.credential }}> (and Content-Type: application/json if you write a payload template), subscribe the events above, and give each subscription a payload template that names the event — e.g. {"event": "m3u_refresh"} — because Dispatcharr's own payload does not carry the event name.
